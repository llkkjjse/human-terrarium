# AI 驱动的人类生态箱设计规格

日期：2026-09-29

## 1. 背景与目标

现有版本已经具备浏览器地图、居民移动、基础事件、存档和时间推进，但居民行为主要来自固定规则，缺少可解释的个人生活、真实资源约束、信息差和社会因果链。

本次改造的目标是把项目升级为一款本地单机运行、由 DeepSeek 辅助驱动的“人类生态箱”：玩家先定义社会，再观察 24 名居民在不同性格、阶级、资产、关系和认知下生活。玩家可以通过自然语言颁布社会政策、给单个居民设定目标或特性，也可以直接注入必定发生的社会事件。

成功标准：

- 自然语言政策可以被编译为结构化社会规则，并持续影响居民决策和本地结算。
- 每名居民拥有稳定的个人数据、生活节奏、资源、关系、认知和永久历史，而不只是随机交流。
- AI 每个时间帧为全部 24 名居民生成意图；本地规则引擎结算资产、伤害、死亡、证据、逮捕等事实。
- 玩家能够阅读完整对话，并在选中某名居民后查看其一段时间内的详细生活。
- 犯罪、疾病、失业、破产、抗议、骚乱和死亡来自可追踪的因果链。
- DeepSeek 不可用或输出无效时暂停当前帧，不伪造离线结果。

## 2. 非目标

- 第一版不提供云端账户、多人联机、公共服务器或远程存档。
- 第一版不让大模型直接修改数据库或宣布已经发生的资金转移、死亡、逮捕等事实。
- 六项属性只用于塑造策略倾向和规则参数，不实现 D&D 掷骰、职业或战斗规则。
- 不把每次表单编辑、滑块拖动、普通走路或日常小动作写入全局时间线。
- 不要求自动清理个人历史；清理只允许由玩家主动执行。

## 3. 核心原则与优先级

每帧的行为意图按以下优先级解释：

1. 世界数据结构与不可破坏的系统约束
2. 玩家注入的绝对事件
3. 玩家填写的自然语言自定义特性
4. 玩家指派的个人目标
5. 生存和紧急需求
6. 社会政策、法律和环境
7. 居民自己的长期目标
8. 日常作息

绝对事件改变事实并必定发生。自定义特性改变居民的选择方式，优先于目标，但不能取消已经发生的绝对事件。个人目标驱动尝试，不保证成功。社会规则、资源、其他居民和突发事件都可能阻止目标实现。

普通生成居民的自定义特性字段为空。该字段只能由玩家输入自然语言；AI 每帧读取原文，不得改写、补全或自动生成。自定义特性默认是私密信息，只有行为表现或主动交流才可能使他人形成相关认知。

## 4. 总体架构

```text
React 控制台 ───────────────┐
  社会创建 / 政策编辑       │
  居民镜头 / 历史 / 对话     ├── TypeScript 模拟核心 ── IndexedDB
  时间控制 / 绝对事件       │      规则结算、知识传播、历史
Phaser 地图 ────────────────┘
          │
          └── 127.0.0.1 Node AI 网关 ── DeepSeek API
```

边界如下：

- React/Phaser 负责输入、观察和表现，不拥有权威模拟状态。
- TypeScript 模拟核心拥有世界事实、规则结算、随机数、时间推进和事件聚合。
- Node AI 网关保存 API 密钥，负责调用、超时、JSON 修复、用量记录和响应校验前的协议封装。
- DeepSeek 负责理解自然语言、规划行为、生成对话和提出候选事件，不负责最终结算。
- IndexedDB 保存可恢复的权威状态与永久历史。

## 5. 世界与居民数据

### 5.1 社会蓝图

`SocietyBlueprint` 至少包含：

- 社会描述原文与编译摘要
- 贫富差距、阶层流动和社会信任
- 住房供给、租售价格、区域声望
- 就业岗位、工资、物价、债务环境
- 治安能力、腐败程度、犯罪压力
- 医疗、教育和福利水平
- 文化偏好、邻里关系和八卦传播倾向
- 地区、道路、住宅、商铺、工作场所、医院和治安设施
- 生效中的结构化政策

### 5.2 居民

世界固定生成 24 名居民。每名居民包含：

- 身份：姓名、年龄、家庭、住址、工作和社会职责
- 六项属性：力量、敏捷、体质、智力、感知、魅力
- 性格：道德、风险偏好、冲动、野心、同理心、服从性等连续值
- 自定义特性：玩家输入的自然语言字符串，默认空白
- 外观：衣着、交通工具、住宅可见状况和低调程度
- 经济：现金、收入、债务、物品、房产、车辆和所有权记录
- 状态：健康、疾病、受伤、疲劳、饥饿、压力和法律状态
- 社会：关系、声誉、职责、真实阶层和被感知阶层
- 行为：作息、当前计划、个人目标、长期目标和最近行动
- 认知：对人、地点、资产、事件的主观知识与传闻

自然生成的六项属性范围为 1–20。玩家后续编辑的角色不受 20 上限限制，但仍须是有限数值。属性不是成功判定本身，而是影响居民倾向采用的方法。例如身无分文却被要求买房时，高力量且低道德者可能倾向抢劫，高智力者可能倾向诈骗，高魅力者可能借贷或说服，高感知者可能寻找目标与机会，高体质者可能选择长期体力劳动。

真实阶层由收入、资产、债务、住房、职业和声誉动态计算。被感知阶层单独计算，受住宅、车辆、衣着、消费、地区、低调程度和流言影响。居民和 AI 不得直接读取他人不可见的真实资产。

### 5.3 关系、知识和记忆

关系记录亲密、信任、恐惧、债务、敌意和最近互动。知识记录至少包含主题、主观内容、来源、可信度、获得时间和最后更新时间。知识可能正确、错误、过时、夸张或故意伪造。

信息只通过可解释渠道获得：现场观察、工作接触、家庭与邻里关系、公共消息、调查或对话。八卦传播可以遗漏和扭曲内容。选择犯罪目标时使用居民所知道或相信的财富与路线，本地结算才读取目标的真实资产。

## 6. 世界生成流程

开始新世界前显示社会创建向导：

1. 玩家填写自然语言社会描述，并可调整贫富、住房、就业、治安、福利、信任等结构化轴。
2. 前端调用 `POST /api/world/generate`。
3. DeepSeek 把描述编译为 `SocietyBlueprint`，并生成 24 名候选居民。
4. 本地验证器检查引用、角色覆盖、阶层分布、资产所有权、总量约束和必要设施。
5. 无法满足约束时返回可读错误，不创建半成品世界。
6. 玩家在预览页编辑社会与居民；确认后才写入正式世界。

世界一旦确认，居民基础数据即确定。后续变化必须来自模拟或玩家显式编辑，并留下审计记录。

## 7. DeepSeek 网关与配置

本地 Node 网关仅监听 `127.0.0.1`。浏览器只访问本地网关，不接触 API 密钥。配置保存在不提交 Git 的 `.env.local`：

```dotenv
DEEPSEEK_API_KEY=your_key_here
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

网关提供：

- `POST /api/world/generate`：编译社会蓝图并生成候选居民。
- `POST /api/policy/compile`：把已提交的自然语言政策编译成结构化规则。
- `POST /api/frame/run`：为当前时间帧生成 24 名居民的行为意图、对话和候选事件。

绝对事件的自然语言解析使用独立的按需 AI 调用，但解析后的结构化变更由本地引擎执行。政策只在正式提交或修改时重新编译，不在每帧重复解析。

网关使用严格 JSON 输出、Zod 校验、超时和一次 JSON 修复调用。每次调用记录模型、请求类型、开始时间、耗时、输入/输出 token、估算费用、结果状态和错误摘要，永不记录 API 密钥。

## 8. 帧协议与上下文控制

玩家可选择 AI 帧粒度：1 小时、12 小时或 1 天。播放控制与帧粒度分离，包含暂停、单步、连续运行和快速长期观察。连续运行仍然逐帧等待 AI 与本地结算完成；暂停在当前请求结束后生效。

正常模拟中，每帧只调用一次 `POST /api/frame/run`，批量处理全部 24 名居民。请求包含：

- 社会摘要和当前政策
- 上一帧状态增量
- 24 名居民的压缩档案与当前状态
- 每人的自定义特性、个人目标和当前计划
- 与本帧有关的关系和主观知识
- 待执行的绝对事件
- 最近关键记忆、长期摘要和按相关性选出的旧记忆

请求不包含完整永久历史、精确渲染坐标或无关旧事件。稳定的提示前缀和社会摘要应尽量保持字节一致，以利用上下文缓存。未变化居民允许返回 `continue`，但 24 名居民必须各有一个动作项或 `continue`。

响应采用以下形状：

```json
{
  "residentActions": [
    {
      "residentId": "r-07",
      "action": "select_target_for_fraud",
      "targetId": "r-19",
      "locationId": "commerce",
      "reason": "认为目标富有且容易接近",
      "planChange": "尝试取得信任",
      "dialogue": []
    }
  ],
  "conversations": [],
  "candidateEvents": [],
  "memoryUpdates": []
}
```

协议要求：

- 引用只能指向请求中存在的居民、地点、资产、政策和事件。
- AI 只能提出意图，不能直接宣布完成资产转移、伤害、死亡、逮捕或判罚。
- 对话只有在时间、地点和接触条件允许时才有效，并保存完整原文。
- 生成意图必须显式考虑自定义特性，其次考虑玩家个人目标。
- 被选中的居民获得较详细的理由、计划和生活描述；其他居民保持压缩输出。

## 9. 单帧处理顺序

每帧严格按以下顺序执行：

1. 解析并应用本帧玩家绝对事件。
2. 应用已编译政策和个人目标变更。
3. 构造压缩世界状态和居民上下文。
4. 批量调用一次 DeepSeek。
5. 校验 24 名居民的意图、候选事件和对话。
6. 本地规则引擎结算移动、工作、消费、资产、健康、犯罪、证据和执法。
7. 更新关系、主观知识、流言和记忆。
8. 为每名居民写入永久生活记录和完整对话。
9. 聚合值得公开的全局事件。
10. 提交事务并推进世界时间。

步骤 1–9 作为一个逻辑事务。AI 失败或输出无效时不推进时间，不留下半帧结果。

## 10. 本地规则结算

规则引擎是世界事实的唯一裁判。它使用已有状态、可复现随机源、地点、时间、参与者属性和 AI 意图生成结果。

日常系统至少覆盖睡眠、进食、通勤、工作、收入、消费、社交、休闲、照护、疾病进展和恢复。居民即使没有发生交流，也必须继续生活并消耗时间与资源。

犯罪与执法使用多阶段状态机：

```text
动机 → 基于主观知识选择目标 → 接近 → 实施
     → 资产/受伤/死亡结算 → 目击与证据
     → 报案或隐瞒 → 治安人员调查 → 锁定嫌疑人
     → 追捕/逮捕/逃脱 → 处罚或悬案
```

抢劫对象是否真的有钱，由目标的真实资产决定。是否被捕取决于时间地点、目击者、监控、物证、赃物、伤势、作案计划、事后行为、治安能力、腐败、骚乱状态，以及负责治安居民的能力、性格、关系、偏见和实际行动。治安官也是普通居民，不拥有全知视角。

疾病、事故、失业、破产、家庭冲突、谋杀、抗议和骚乱使用相同的因果原则：候选原因可以由 AI 提出，触发条件与后果由规则结算，并把原因、参与者、结果和后续影响链接到同一因果链。

## 11. 玩家干预

### 11.1 社会政策

玩家在自然语言编辑器中起草政策。输入和拖动控件只改变草稿，不写时间线。点击“正式实施政策”后才调用编译接口；编译成功生成一条政策事件并开始影响后续帧。

### 11.2 个人目标

玩家可给单个居民输入目标。目标拥有高优先级，但居民会按自身属性、性格、资源、阶层和认知选择手段，结果可能失败，也可能引发犯罪、负债、受伤或法律后果。

### 11.3 自定义特性

居民编辑页提供自然语言自定义特性栏，默认空白。特性每帧原样注入该居民上下文，优先于个人目标。若特性与目标冲突，行为必须服从特性；若绝对事件与特性冲突，绝对事件仍发生，特性只影响居民之后的情绪、解释和反应。

### 11.4 绝对事件

玩家可以在居民页或全局入口安排下一步必定发生的事件。DeepSeek 只把原文翻译为结构化世界变更；本地校验只检查模式、引用和可执行性，不以“不现实”为由否决。事件执行后以红黑醒目标识显示“玩家强制事件”，保留原文、直接状态变化和后续因果事件，且不能被全局时间线过滤器隐藏。

## 12. 界面与观察体验

主界面由地图、社会控制区、全局时间线和居民镜头组成：

- 地图显示居民、住宅、车辆、设施和可见的生活水平；低调富人可能不显富。
- 社会控制区提供政策草稿、正式实施、帧粒度、播放速度、AI 状态、token 和估算费用。
- 全局时间线只显示政策、绝对事件、重病与死亡、重大财富或阶层变化、犯罪与调查、逮捕、抗议、骚乱和群体冲突。
- 普通移动、作息、滑块变化和未提交草稿不进入全局时间线。

选中居民后打开“居民镜头”，至少提供：

- 档案、真实阶层与资产、被感知阶层
- 六项属性、普通性格、自定义特性
- 当前计划、玩家目标和个人长期目标
- 作息、工作、健康、消费和资产变化
- 关系网络与主观知识
- 永久生活史和所有完整对话
- 犯罪、证据、调查和法律状态
- 居民编辑与绝对事件安排

生活史使用分页或虚拟列表，支持按时间、类型和关联人物过滤。每次帧粒度切换或拖动速度控件只影响控制状态，不制造观察事件。

## 13. 持久化与迁移

IndexedDB 新版本至少包含：

- `worlds`：世界快照、社会蓝图、政策和当前时间
- `residents`：24 名居民的当前权威状态
- `lifeLogs`：个人永久生活记录
- `conversations`：完整对话文本与参与者
- `events`：全局事件和因果链
- `knowledge`：居民主观知识与来源
- `memories`：近期记忆、长期摘要和相关性索引
- `aiRuns`：AI 请求的状态、耗时、token、费用和错误

现有存档从 v1 迁移到 v2。迁移保留原世界和事件，将缺失字段填入明确默认值，并在首次载入时创建新表记录。迁移必须可重复执行且不重复居民、资产或事件。

所有原始生活记录和对话永久保存。AI 上下文通过近期窗口、长期摘要和相关检索保持有界，不能因为历史增长而把全部记录发给模型。界面显示存储占用，允许导出和玩家主动清理，但永不自动删除。

## 14. 错误、恢复与安全

- 网络、超时、余额不足或网关不可达：暂停当前帧，显示原因、重试按钮和本次用量；世界时间不推进。
- JSON 语法或模式错误：允许一次修复调用；仍无效则暂停。
- 不存在的引用、重复居民或 AI 直接声明权威结果：拒绝整帧。
- 单个居民行为违反其自定义特性：拒绝该行为并请求一次针对该居民的修复；仍失败则拒绝整帧。
- 本地结算或写库失败：回滚整个逻辑事务并保留可重试输入。
- 不提供静默本地 AI 替代，不把固定规则生成的行为伪装成大模型结果。

API 密钥只存在于 Node 进程环境，不能写入前端包、IndexedDB、日志、导出文件或 Git。网关限制请求体大小、校验本地来源、隐藏上游错误中的敏感字段，并默认只监听回环地址。

## 15. 性能与成本

- 24 名居民共享一次帧调用，避免逐人请求。
- 默认使用 `deepseek-flash` 和严格 JSON；每帧采用非思考或低推理配置。
- 未变化居民返回 `continue`；动作使用稳定的短代码，描述只在需要观察时展开。
- 选中居民获得更多输出预算，其余居民只返回决策所需字段。
- 政策编译、世界生成和绝对事件解析是按需调用，不混入每帧成本。
- 保持系统提示、社会摘要和字段顺序稳定，以提高上下文缓存命中。
- 快速模式通过选择 12 小时或 1 天帧并连续执行实现，不跳过规则结算。

## 16. 测试策略

自动测试默认使用模拟 AI，不消耗真实 DeepSeek API。真实 API 只用于手动验收。

单元与属性测试覆盖：

- 自定义特性优先于个人目标，绝对事件优先于两者。
- 自然居民属性限制在 1–20，玩家编辑值可超过 20。
- 资产所有权和资金变化守恒，不生成不存在的资产。
- AI 引用、24 人动作完整性和权威结果禁令。
- 作息、健康、犯罪证据、调查和逮捕因果链。
- 主观知识与真实资产隔离，八卦可以失真但来源可追踪。
- 给定相同世界状态、相同 AI 决策和相同随机种子，结算结果一致。
- 超时、无效 JSON、重复居民、虚构引用和修复失败时不推进时间。
- v1 到 v2 迁移可重复且不丢数据。

端到端测试覆盖：

1. 创建社会并生成 24 名居民。
2. 正式实施自然语言政策并观察其结构化影响。
3. 给居民设置目标与冲突特性，验证特性优先。
4. 注入绝对事件，验证其必定执行且醒目展示。
5. 执行多个帧并查看全局时间线、居民生活史和完整对话。
6. 模拟 AI 故障，验证暂停、重试和事务回滚。
7. 刷新页面后恢复世界与全部历史。

## 17. 验收条件

- 本地配置 DeepSeek 密钥后，一条命令可同时启动前端和回环 AI 网关。
- 玩家能创建并确认一个拥有 24 名居民的社会，所有居民字段与引用通过校验。
- 1 小时、12 小时、1 天三种帧均以每帧一次批量 AI 调用运行。
- 每名居民在每帧都有动作或 `continue`，并由本地引擎产生最终事实。
- 居民没有交流时仍会工作、休息、消费、生病和处理个人事务。
- 对话原文可见；选中居民可浏览永久生活史；全局时间线不被日常细节淹没。
- 犯罪和重大事件能够显示从动机到后果的因果链，治安人员不具备全知信息。
- 自定义特性、个人目标和绝对事件严格遵守规定优先级。
- AI 故障不会推进世界或写入半帧状态，API 密钥不会离开本地网关。
- 自动化测试、类型检查、生产构建和关键端到端流程通过。

## 18. 实施边界

实施应在现有 React、Phaser、TypeScript、Zod、Dexie、Vitest 和 Playwright 技术栈上渐进改造，不重写地图渲染和现有可复用的模拟基础。建议按数据模型与迁移、规则结算、AI 网关与协议、世界生成、控制台与居民镜头、持久化历史、端到端验收的依赖顺序推进。

第一版以可观察、可恢复、因果一致为优先，不扩展多人、云部署、向量数据库或复杂 3D 表现。
